## Context

Мотивация — в `proposal.md`, требования — в `specs/generator-workspace`, `specs/generator-settings`, `specs/session-state`.

### Текущее состояние, от которого отталкиваемся

**Раскладка.** `ui/Generator/Generator.tsx` — одна строка `w-desktop`: слева лист, справа аккордеон из пяти секций. Тема в `@theme` — два токена, акцент `violet-*` и серые `zinc-*` захардкожены в классах.

**Предпросмотр.** `PagePreview` рисует canvas в основном потоке тем же `renderPageLayers`, что и экспорт. Ширина фиксирована: `PAGE_WIDTH = 700`, `previewScale = 700 / sheet.width`. Воркер `createPageRenderClient` отдаёт JPEG-блоб в заданном масштабе, его вызывают только экспорт и пачка.

**Рецепт до картинки не доходит.**
- `usePageRender` и `useRunRender` берут `state.inkColor`, `state.flags` и `state.seed` напрямую из стора, а не из рецепта.
- `isInkColorAuto` меняет только рецепт, а рецепт в этой части никто не читает.
- `seed` почерка увеличивается на `setText` и `toggleDistortion` — это нарушает `run-recipe` («Правка текста сохраняет параметры почерка»).
- `startNewRun`, то есть новый `runSeed`, из UI не вызывается.

**Мёртвые поля стора.** Отрисовка и раскладка не читают `fontSize`, `blockWidth`, `lineSpacing`, `topOffset`, `leftPadding`, `blockRotate`, `backgroundId`, `customBackgroundSrc`, `selectBackground`, `setCustomBackground`. `isBackgroundHidden` рендер читает, но контрола у него нет.

**Хранилище.** Свои листы лежат в `localStorage` под префиксом `autograph.paper.*`: фото, производные, индекс. Больше ничего не сохраняется, undo нет.

**Тесты, завязанные на текущую разметку:** `settings-panel`, `paper-group-*`, `save-bar`, `batch-export`, `page-preview`, `routes`, `ui-primitives`, а также 55 скриншотных эталонов.

### Ограничения

- Desktop-only, окно ≥ 1280 px.
- FSD-границы проверяет steiger.
- Ядро `lib/*` не меняется.
- Нельзя ослаблять требования `page-render`: предпросмотр и экспорт — один путь отрисовки, отрисовка в полном разрешении идёт вне основного потока.

## Goals / Non-Goals

**Goals:**

- Экран с нуля по спекам; от текущей вёрстки берутся только модельные хуки: импорт и перемер листа, свой шрифт, экспорт, пачка.
- Отрисовка берёт чернила и почерк из рецепта; единственный источник случайности — `runSeed`.
- Стор делится на три части: документ (сохраняется и попадает в историю), просмотр и ресурсы.
- Дизайн-токены, которыми пользуются все три экрана.

**Non-Goals:**

- Адаптив под планшет и телефон, светлая тема и переключение тем.
- Сохранение своего шрифта и своего изображения сцены между сессиями. Шрифт в `localStorage` не влезет рядом с фото листов, а IndexedDB — отдельная работа.
- Markdown-форматирование, фотоэффекты — отдельные change из того же explore.
- Правка контура и изгиба листа руками: вне `paper-profile`.
- Перенос предпросмотра уровня «вписать» в воркер.

## Decisions

### D1. Раскладка: три колонки и полоса действий

```
┌──────────────────────────────────────────────────────────────────────────┐
│ Autograph                               ↶ ↷        Свой шрифт →          │ шапка 48
├───────────────┬──────────────────────────────────────┬───────────────────┤
│ ТЕКСТ         │  ‹ 3 / 12 ›   ▯ ▯▯     − 38% + Вписать│ БУМАГА            │
│┌─────────────┐│  ┌────────────┐┌────────────┐        │ [▦][☰][▦][+ фото] │
││             ││  │            ││            │        │ ПОЧЕРК            │
││  textarea   ││  │  стр. 5    ││  стр. 6    │        │ [Abram        ▾]  │
││  во всю     ││  │            ││ (зеркало)  │        │ ЧЕРНИЛА           │
││  высоту     ││  │            ││            │        │ (A)● ● ● ● ● ● ●  │
││             ││  └────────────┘└────────────┘        │ РЕАЛИЗМ           │
│└─────────────┘│                                      │ [Ровно|Акк|Обыч|Неб]│

├───────────────┴──────────────────────────────────────┴───────────────────┤

      360 px                      ≥ 540 px                    340 px
```

- Экран — сетка на высоту окна (`100dvh`), прокручиваются колонки, а не страница. Поэтому полоса действий видна всегда и без `position: fixed`.
- Текст занимает слева всю высоту: это основной ввод, а пачка — главный сценарий, текст длинный. Под полем — счётчик знаков и число страниц.
- Панель инструментов области просмотра лежит поверх листа, в её верхней части: навигация, переключатель «одна страница / разворот», масштаб.
- Ссылка «Как создать свой шрифт» переезжает в шапку. Рядом с «Свой шрифт» в настройках почерка — подсказка со ссылкой туда же.

Отвергнуто — вертикальный рейл иконок из explore-эскиза. При пяти решениях основного пути второй уровень навигации ничего не даёт, а экспертный режим — один раскрывающийся блок.

### D2. Визуальный язык: тёмная тема

Тема остаётся тёмной, это решение пользователя. Панели — тёмные нейтральные, акцент — «чернильный» синий.

Фотография листа светлая, и на тёмном фоне у неё теряются края и рамка листа. Поэтому область просмотра на ступень светлее панелей, а у листа своя тень и тонкая обводка (`--shadow-sheet`) — они держат контур листа.

Токены в `@theme` (`src/app/styles/app.css`), классы используют только их:

| Группа | Токены |
|---|---|
| Поверхности | `--color-canvas` (область просмотра, на ступень светлее панелей), `--color-surface` (панели), `--color-surface-raised` (карточки, поповеры), `--color-border`, `--color-border-strong` |
| Текст | `--color-fg`, `--color-fg-muted`, `--color-fg-subtle` |
| Акцент | `--color-accent`, `--color-accent-hover`, `--color-accent-fg`, `--color-focus` (кольцо фокуса) |
| Состояния | `--color-danger`, `--color-success` |
| Типографика | `--font-ui` (system-ui-стек), размеры `--text-xs…--text-lg`, подписи секций — капс `xs` с разрядкой |
| Формы | `--radius-sm/md/lg`, `--shadow-sheet` (тень и обводка листа), `--shadow-popover` |
| Размеры | `--spacing-desktop: 80rem`, `--spacing-text-panel`, `--spacing-settings-panel`, `--spacing-header`, `--spacing-action-bar` |

Цвета — в `oklch`, как в текущем токене. Точные значения подбираются в задаче токенов по контрасту: WCAG AA для текста, `a11y`-проверки stories это ловят.

Отвергнуто — светлая тема со «столом» тёплого серого: фотографию она подаёт лучше, но пользователь выбрал тёмную. Край листа решают обводка и тень. Светлая тема и переключение тем — Non-Goal.

### D3. Стор: документ, просмотр, ресурсы

`useGeneratorStore` остаётся одним zustand-стором, но с тремя явными частями.

- **Документ** — то, что сохраняется и попадает в историю:
  - `text`;
  - `fontFamily` — только встроенный;
  - `ink: {kind: 'auto'} | {kind: 'tone', toneId} | {kind: 'custom', color}`;
  - `familyId`, `sheetId`, `isSheetPinned`;
  - `realism: {level: RealismLevelId | 'custom', flags, wordFrequency, letterFrequency, hasContourVariance}`;
  - `geometryCorrection`, `bottomMargin`;
  - `scene` — параметры и флаги без изображения;
  - `runSeed`.
- **Просмотр:** `pageIndex`, `isSpread`, `zoom: 'fit' | number`.
- **Ресурсы:** `presetFamilies`, `userSheets`, `customFontFamily`, `customSceneSrc`, `isBackgroundHidden`.

Уходят `seed` и мёртвые поля из Context. `ink` заменяет пару `inkColor` + `isInkColorAuto`: вариант «из палитры» должен оставаться «Авто»-независимым и подсвечиваться в свотчах по `toneId`, а не по сравнению строк цвета.

Отвергнуто — отдельные сторы под документ и просмотр. Селекторы параметров страницы читают обе части сразу, а `useShallow` через два стора не работает.

### D4. Отрисовка читает рецепт

`selectRunRecipe` уже строит рецепт из `runSeed`. Сборка параметров страницы (`model/buildPageRenderParams.ts` и вызывающие `usePageRender` / `useRunRender`) берёт:

- цвет чернил — `recipe.inkColor`; рецепт сам отдаёт ручной цвет при `kind !== 'auto'`;
- флаги, частоты и seed почерка — `recipe.handwriting`.

Флаги и частоты рецепт копирует из `realism` документа, случайный в нём только seed.

«Перегенерировать» = `startNewRun`: новый `runSeed`. Правка текста и реализма `runSeed` не трогает. Тест `run-recipe` «Повторяемость прогона» и лента вызовов рендерера закрепляют, что других источников нет.

### D5. Уровни реализма — таблица в конфиге

`config/realismLevels.ts` — упорядоченный список ступеней. Каждая ступень — `{id, label, flags, wordFrequency, letterFrequency, hasContourVariance}`. Начальное предложение:

| Ступень | Искажения | Частоты (слово / буква) | Контуры |
|---|---|---|---|
| Ровно | все выключены | — | выкл |
| Аккуратно | поворот слова, сдвиг строки | 1 / 1 | вкл |
| **Обычно** (дефолт) | + наклон слова, сдвиг слова, расстояние между буквами | 2 / 2 | вкл |
| Небрежно | все, кроме подмены шрифта буквы | 4 / 3 | вкл |

Выбор ступени пишет её значения в `realism`. Правка любого поля в экспертном режиме ставит `level: 'custom'`. Уровень хранится явно, а не выводится сравнением с таблицей: иначе ручной набор, случайно совпавший со ступенью, и правка таблицы в будущем меняли бы подпись у сохранённых сессий. Числа ступеней подбираются на глаз в задаче D5 по stories; спека требует только порядок, дефолт и крайние ступени.

### D6. Область просмотра: вписывание, зум, разворот

**Масштаб** хранится как доля пикселей кадра (`zoom = 0.25` → 25 %); `'fit'` вычисляется из размера области через `ResizeObserver`. Шаги кнопок: 10 %…400 %, геометрическая лестница. Ctrl/⌘ + колесо зумит вокруг курсора. При масштабе больше вписанного лист прокручивается в контейнере, пробел + перетаскивание панорамирует.

**Растр предпросмотра — двухуровневый:**
- *Основной* — canvas в основном потоке, как сейчас, но с масштабом `min(zoom, fitZoom) × devicePixelRatio`, а не с фиксированными 700 px. Это тот же путь `renderPageLayers`.
- *Детальный* — когда `zoom × DPR` превышает основной, после остановки зума (debounce ~250 мс) страница заказывается у воркера `createPageRenderClient` в масштабе `min(zoom × DPR, 1)` и ложится поверх основного. Пока заказ идёт, основной растр растянут CSS-трансформом. Новая правка отменяет заказ через `AbortSignal`.

Так требование `page-render` «в полном разрешении — вне основного потока» держится и для зума, а «предпросмотр = экспорт» — тем более: детальный растр и есть экспорт в своём масштабе.

Отвергнуто:
- всё через воркер — задержка на каждый набранный символ (кодирование JPEG) при вписанном листе;
- всё в основном потоке — зум 100 % на кадре 3000×4000 замораживал бы интерфейс на сотни миллисекунд.

**Разворот:** два холста рядом — `2k−1` слева, `2k` справа. Зеркалирование делает `mirrorSheetRuling` / рендерер — оно и так у чётной страницы. «Вписать» в развороте считается по паре. `pageIndex` остаётся индексом страницы; разворот его не меняет, навигация шагает на 2 и выравнивает на нечётную. «Сохранить страницу» сохраняет страницу `pageIndex`, в развороте она подсвечена рамкой, клик по второй странице делает текущей её.

### D7. Сессия: zustand `persist` с по-полевой проверкой

Используем `persist` из `zustand/middleware`, новой зависимости нет:

- ключ `autograph.session`;
- `version: 1`;
- `partialize` — документ плюс `isSpread`;
- хранилище — обёртка над `localStorage` с `try/catch` на запись: переполнение и запрет молча выключают сохранение.

Чтение идёт через свой `merge`: `model/sessionSchema.ts` проверяет каждое поле по отдельности (типы, диапазоны, `toneId` в палитре, `level` в таблице) и подставляет дефолт в негодное.

Ссылки на листы проверяются **после** `restoreUserSheets` и загрузки профилей: закреплённый `sheetId`, которого нет, снимает закрепление, неизвестная семья → первая. Поэтому проверка ссылок — отдельный шаг в `useStoredUserSheets` / `usePaperProfiles`, а не в `merge`: в момент `merge` свои листы ещё не прочитаны.

Запись дросселируется (~500 мс): набор текста иначе писал бы `localStorage` на каждый символ.

Отвергнуто — IndexedDB: сессия мала, а свои листы уже живут в `localStorage`, два механизма хранения ради нескольких килобайт не окупаются.

### D8. История правок — свой срез в сторе

Своя реализация без зависимостей: `past` и `future` — массивы снимков документа, глубина — 100 шагов. Снимок — неизменяемый объект документа (десятки килобайт даже с длинным текстом).

Все экшены документа идут через одну обёртку `commit(patch, {coalesceKey?})`:
- набор текста — `coalesceKey: 'text'`, склейка шагов в окне ~800 мс;
- слайдеры коммитят шаг на `onValueCommit`; во время перетаскивания пишется только текущее значение без шага истории.

Просмотр и ресурсы в историю не попадают. Удаление своего листа, на который ссылается снимок, разрешается тем же шагом проверки ссылок, что в D7.

Клавиши — один обработчик на документ. Ctrl/⌘+Z и Ctrl/⌘+Shift+Z (плюс Ctrl+Y) перехватываются **и в поле текста** с `preventDefault`. Поле текста контролируемое и получает значение из истории, а посимвольный undo браузера после программной установки значения ведёт себя непредсказуемо.

Отвергнуто — `zundo`: его склейку шагов и исключение полей всё равно пришлось бы настраивать своими обёртками, а объём своей реализации сопоставим.

### D9. Компоненты и слои FSD

- **`shared/ui` — новые примитивы:**
  - `SegmentedControl` (Radix Toggle Group) — уровни реализма, одна страница / разворот;
  - `TileRadio` (на Radix Radio Group) — семьи листов;
  - `Swatch` / `SwatchGroup` — чернила;
  - `Dialog` (Radix Dialog) — настройка своего листа;
  - `Disclosure` (Radix Collapsible) — экспертный режим;
  - `IconButton` и `Toolbar` — панель просмотра и шапка;
  - `ValueSlider` — слайдер с подписью значения, единицей и форматтером; старый `Slider` становится его основой.

  `Accordion` и `ColorInput` остаются: `ColorInput` — в экспертном режиме, `Accordion` — внутри экспертного режима по группам.
- **`widgets/AppHeader`** — шапка трёх экранов со слотом действий страницы: генератор кладёт туда undo/redo. Три потребителя — повод поднять её из `pages`, это первый код в `widgets`.
- **`pages/Generator/ui`:**
  - `TextPane`;
  - `SheetViewport` (`ViewportToolbar`, `PageCanvas`, `SpreadView`);
  - `SettingsPane`: `PaperPicker`, `HandwritingPicker`, `InkPicker`, `RealismPicker`, `ExpertSettings`;
  - `SheetDialog` (поля границ и разлиновки, перемер, удаление);
  - `ActionBar` (перегенерация, сохранение, пачка с прогрессом).

  Хуки `useSheetImport`, `useSheetRemeasure`, `useCustomFont`, `useExportPage`, `useBatchExport` переезжают без изменения логики.

**Диалог листа.** Работает с черновиком. Подтверждение делает `addUserSheet` с `buildSheetRuling` — ту же операцию, что `RulingForm` сейчас, так что правило «изгиб и перспектива сохраняются, если шаг и фаза совпали до сотых» не меняется. Если автоопределение не удалось, `useSheetImport` открывает диалог на этом листе.

**Единицы.** Форматтеры — `pages/Generator/lib/format/`: доли шага со знаком, градусы, px, проценты, словесная шкала частот 1–5 («очень редко» … «очень часто»).

### D10. Тесты

- **Юнит:**
  - таблица реализма → рецепт;
  - `sessionSchema` на каждое негодное поле;
  - история: склейка, глубина, очистка повтора;
  - проверка ссылок на листы после восстановления;
  - параметры страницы берут `recipe.inkColor` и `recipe.handwriting`;
  - форматтеры;
  - расчёт `fitZoom` и лестницы масштаба.
- **Компонентные** (jsdom), по одному файлу на область:
  - закреплённые действия;
  - навигация клавишами вне и внутри поля текста;
  - разворот (пары, непарная последняя);
  - диалог листа (подтверждение, отмена, автооткрытие при неудаче);
  - экспертный режим;
  - undo/redo кнопками и клавишами;
  - восстановление сессии.

  Старые тесты панели, `paper-group-*`, `save-bar`, `page-preview` удаляются вместе с компонентами. Их проверки поведения — импорт, перемер, правка разлиновки, пачка, ошибка шрифта — переносятся в новые файлы, а не теряются.
- **Stories в браузере:** `BaselineFit`, `RealLayout`, `RasterRuling` переводятся на `SheetViewport`. Добавляются проверка «кнопки действий в окне 1440×900 при раскрытом экспертном режиме» и `a11y` всех новых stories.
- **Скриншоты:** эталоны переснимаются в docker целиком; старые файлы эталонов удаляются.

## Risks / Trade-offs

- **[Детальный растр через воркер на каждое изменение при зуме]** → debounce и отмена по `AbortSignal`. Пока нет заказа, основной растр растянут: при быстрой правке на 300 % лист на долю секунды мыльный. Это приемлемо.
- **[Переполнение `localStorage`]** Фото своих листов уже занимают квоту, запись сессии может упасть → обёртка глотает ошибку записи, сессия просто не сохраняется (сценарий в спеке). Раздел `paper-profile` не трогаем.
- **[Смена единственного источника случайности меняет картинку при том же seed]** Отрисовка переходит на `recipe.handwriting.seed` вместо `state.seed` → эталоны stories с фиксированным seed переснимаются. Сохранённых сессий до этого change нет, миграция не нужна.
- **[Переписывание всех UI-тестов разом теряет покрытие]** → задачи идут по областям. Каждая старая проверка поведения перечислена в задаче переноса, старый тест удаляется только в той же задаче, где появляется новый.
- **[Восемь шрифтов грузятся при открытии списка почерков]** → списки отрисовываются по требованию; `@font-face` с `font-display: swap`, до загрузки название показывается системным шрифтом.
- **[Точные ступени реализма субъективны]** → таблица в конфиге правится без изменения спеки и кода.

## Migration Plan

- Данных для миграции нет: сессия до этого change не сохранялась, записи своих листов не меняются.
- Выкатка — обычный деплой GitHub Pages из `master`.
- Откат — revert коммитов change. Ключ `autograph.session` старая версия не читает, он ей не мешает.
