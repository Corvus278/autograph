База прогона: `ab338cc`
Гейт: `npm run lint && npm test`
Быстрые проверки: `npm run typecheck`, `npx vitest run --project=unit tests/<файл>.test.ts`
Долгие слои: `npm run build:paper`, `npm run test:stories`, замер времени 1.4/8.4 — группа G7
Хук коммита: `tsc` + `vitest --changed` — каждая группа оставляет типы и затронутые тесты зелёными (см. K4)

## Контракты

- **K1 Разметка цветом** — `/tmp/false-margin-line/ground-truth.md`: строка на снимок «класс есть/нет, сторона, `x`, `u`
  самый внутренний, ΔR/ΔG по полосам»; скрипт — `/tmp/false-margin-line/ground-truth-script.ts`, вне `detectRuling`.
  Владелец G1; потребители G2, G5, G7, 9.1.
- **K2 Опора** — `/tmp/false-margin-line/baseline.md`: строки `measure:sheet` 26 снимков + 8 пресетов с базы `ab338cc`;
  md5 `profiles.json` = `bbb9e9b963bc092e50aad90f60fd39ce`. Владелец G1; потребители G5, G7.
- **K3 Вето** — кандидат `findMarginLine` принимается, только если та же полосовая мера #9 при заданной его стороне
  (трасса, медиана, `MARGIN_LINE_BAND_COVERAGE`, `isInsideMeasuredBins`, `toMarginLineBarrier`) его подтверждает;
  `x` принятого — от первой ступени до бита; стоит до `refineMarginLine`/`toBendRegion`, на обоих проходах. Результат
  вето — значение с полями «принят, отношение, связавший порог, охват», которое G6 выводит без повторного замера.
  Константы `MARGIN_LINE_*` и `toMarginLineBarrier` не меняются. Владелец G4; потребители G5, G6, G7.
- **K4 Синтетика** — `tests/helpers/synthetic-sheet.ts`: фиксированный лист «причина `IMG_1813`» (схождение клетки,
  черта слева со сносом, без вставной вертикали) и генератор `params → {растр, класс, сторона, u черты}`. Тест 3.1
  фиксирует дефект базы («линия справа»); G4 переворачивает это утверждение в том же коммите, что и вето.
  Владелец G3; потребители G4, G6, 9.1.
- **K5 Вердикт первой ступени** — поле в `MarginLineReport`/`SheetPhotoDiagnostics`: принят | отвергнут вето (отношение,
  связавший порог) | не звался, факт вызова — отдельным полем. Владелец G6; потребитель `scripts/sheet-photo-report.ts`.
