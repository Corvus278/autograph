# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Autograph — генератор рукописного текста: пользователь вводит текст, выбирает рукописный шрифт и лист бумаги — из пресет-пака
или свою фотографию тетради, — сервис рисует страницы в браузере и отдаёт их в JPEG: одну страницу или всю пачку
архивом. Лист приходит фотографией, поэтому текстура, свет и микротени настоящие: чернила им подчиняются, а
геометрия текста выводится из найденной на снимке разлиновки — в том числе на листе, снятом лежащим на столе, где
линии сходятся к дальнему краю.

## Стек и сборка

React 19 + TypeScript (strict) + Vite 7, Tailwind 4, Radix-примитивы, zustand, react-router. Отрисовка страницы —
canvas; чтение контуров шрифтов — `opentype.js`, упаковка пачки — `jszip`. SPA: одна точка входа `index.html`.

```bash
npm install
npm run dev                # dev-сервер, http://localhost:5173 (host: true — доступен по сети)
npm run build              # tsc --noEmit && vite build -> dist/
npm run build:paper        # пересчёт профилей пресет-пака -> public/paper/profiles.json
npm run measure:sheet -- <фото> [grid|lined|blank]   # отчёт по одной фотографии, артефакт не трогает
npm run preview            # раздача dist/, http://localhost:4173
npm run typecheck          # только проверка типов
npm run lint               # eslint + tsc + stylelint + prettier + steiger параллельно
npm run lint:fix           # eslint --fix
npm test                   # vitest: юнит- и компонентные тесты (проект `unit`)
npm run test:stories       # прогон stories в Chromium через Playwright (проект `storybook`)
npm run test:visual        # скриншотные тесты в docker-образе Playwright
npm run test:visual:update # переснять эталоны скриншотов (тот же образ)
npm run storybook          # Storybook на http://localhost:6006
```

Порог браузеров — `.browserslistrc` (`baseline widely available`, версии не фиксированы). `vite.config.ts` читает его
через `browserslist-to-esbuild`.

`npm run build:paper` и `npm run measure:sheet` собираются esbuild-ом в кэш и запускаются node-ом: декодирование jpeg
идёт в Chromium (в node декодера нет, а Playwright уже стоит для скриншотных тестов), сам анализ — чистый TypeScript
из `lib/paper`. Декодер и печать отчёта у них общие (`scripts/sheet-photo-report.ts`), поэтому замер одной
фотографии и пересборка артефакта не расходятся в числах.

Деплой: GitHub Pages, `.github/workflows/deploy.yml` на push в `master`. Сайт живёт в подпапке `/<репозиторий>/`:
базовый путь приходит в сборку через `BASE_PATH` (без него — `/`, так работают dev, тесты и Storybook). Пути к файлам
из `public` в коде и в артефакте профилей идут через `withBasePath` (`shared/lib/url`) — Vite сам переписывает их
только в CSS и `index.html`. Приложение — SPA, а Pages не отдаёт `index.html` на неизвестные пути, поэтому workflow
кладёт его копию в `404.html`, иначе прямой заход на `/create-font` вернул бы 404.

## Как работает генератор

1. **Лист — фотография со своей разлиновкой.** `lib/paper/` описывает семью листов (вид разлиновки: клетка или
   линейка) и её экземпляры-фотографии. Разлиновка принадлежит **экземпляру**: контур листа в кадре, шаг, фаза
   первой линии, наклон в кадре, перспектива, изгиб линий, поля и вертикальная линия поля со стороной — всё в
   пикселях его фотографии, рядом с полем освещения и картой текстуры. Общей меры у фотографий нет: сняты они с
   разного расстояния, а привести их к одному шагу можно только масштабированием, которое уводит текст с линий.
   Семья — группа, внутри которой рецепт раздаёт страницам фон; её вид задаёт только число шагов на строку (в
   клетку пишут через одну). Ненайденное поле — полтора шага от **стороны листа**, а не от края кадра, верхнее
   опускается до ближайшей линии (`lib/paper/sheetRuling.ts`).

   Контур (`SheetOutline`) — четыре угла листа в кадре, а не прямоугольник: лист снят под углом и лежит на столе,
   на обложке, рядом с соседним листом. `null` — лист во весь кадр, как у скана. Всё, что меряется по бумаге —
   разлиновка, поле освещения, карта текстуры, — смотрит только внутрь контура: стол вокруг листа темнее или
   светлее бумаги и увёл бы и уровень света, и порог линий. Меры идут в прямоугольнике, вписанном в контур
   (`lib/paper/resolveSheetBounds.ts`): у выпуклого контура с почти осевыми сторонами каждая сторона
   прямоугольника берётся по внутреннему из двух углов. Отступа внутрь сверх этого нет — первая линия у края
   прямоугольника легла бы в начало профиля, и верхнее поле ушло бы в фолбэк.

   Перспектива (`RulingPerspective`) — не преобразование кадра, а дробно-линейная координата вдоль линий
   (`lib/paper/rulingPerspective.ts`): `U(x, y)` одна у всех точек одной линии и равна `firstLinePhase + k·step` у
   линии `k`, а знаменатель `1 + q_x·(x − x₀) + q_y·(y − y₀)` сводит линии к краю кадра. При нулевых схождениях
   она вычисляется тем же выражением `y − x·tgθ`, что и координата прямой наклонной гребёнки, без единой лишней
   операции — ровный лист не меняется ни в одном числе. Поэтому шаг, фаза, поля и изгиб сохраняют прежний смысл, а
   лист на столе описывается одним добавленным полем `perspective` (`null` — линии идут через равный шаг): слои
   выше меняют `u = y − x·tgθ` на вызов `lineCoordinateAt`, а не заводят вторую геометрию. Обращение
   `lineHeightAt` делит на `1 − a·q`, и вдали от нуля этот знаменатель держит не оно, а измерение: годной
   считается только перспектива, у которой он не ближе половины к нулю во всех углах кадра.

   Изгиб (`RulingBend`) — вертикальные смещения линий поверх прямой наклонной гребёнки на равномерной сетке узлов:
   по `x` узлы стоят в центрах равных полос области с линиями, строки узлов — линии гребёнки по координате вдоль
   линий `u = y − x·tgθ`. Сетка несёт свою меру, поэтому выборке (`lib/paper/sampleRulingBend.ts`) не нужны ни
   ширина кадра, ни шаг. Между узлами по `x` — кубический Катмулл — Ром: гладкая производная нужна повороту букв
   без контура, и на узлах строка не ломается. Смещение положительно вниз, `null` — лист ровный. Поле в разлиновке
   обязательное: забытый перенос изгиба (сборка разлиновки, отражение) ловит компилятор.
2. **Импорт фотографии.** Импорт своего листа, перемер и сборка пресет-пака идут одним путём —
   `lib/paper/measureSheetPhoto.ts`. Сначала ищется контур (`lib/paper/detectSheetOutline.ts`): каждая сторона
   кадра режется на полосы, в каждой берётся перепад яркости между поверхностью и бумагой, по голосам полос
   проводится прямая, крайние полосы не голосуют — там скруглённые углы. Ненайденная сторона остаётся краем кадра:
   лист, снятый впритык, теряет не контур, а одну его сторону. Дальше всё меряется в вырезке — вписанном в контур
   прямоугольнике. Лист во весь кадр вырезки не делает и разбирается ровно как прежде, до бита: копия пикселей не
   бесплатна, а мерить в ней нечего.

   Шаг разлиновки ищется автокорреляцией профиля яркости с уточнением по спектру, угол —
   свипом ±2° по резкости горизонтальных линий со сверкой по вертикалям (`lib/paper/detectSkewAngle.ts`): если угол
   линий размывает вертикали (линию поля, концы линий, линии клетки) ниже половины их лучшей резкости, он уведён
   изгибом, и берётся угол вертикалей. Поля и линия поля ищутся по профилю в предсказанных положениях линий; всё
   найденное сохраняется в разлиновку листа. Сама фотография не выправляется: выпрямление размыло бы текстуру, ради
   которой снимок и берётся. Неудача автоопределения не отбрасывает фотографию, а включает ручной ввод разлиновки
   целиком — шага, фазы и полей (маркер — нулевой шаг разлиновки).

   Перспектива (`lib/paper/detectRulingPerspective.ts`) ищется по тем же прослеженным линиям в пяти вертикальных
   полосах вырезки: по их узлам подгоняются наклон, фаза, шаг и два коэффициента схождения. Записывается она,
   только если пройдёт все проверки сразу — найдено хотя бы шесть линий и 60 % узлов, шаг между крайними линиями
   изменился не больше чем на 15 %, знаменатель `1 − a·q` в углах кадра не ближе половины к нулю, невязка узлов
   меньше пятой доли шага, а расхождение с прямой гребёнкой больше двадцатой: перспектива мельче хранения не
   окупает ни байта, ни пересчёта контуров. Невязка меряется **за вычетом** постоянной по столбцу составляющей:
   изгиб бумаги в полшага иначе уносил бы с собой и перспективу, хотя меряется он отдельно и поверх неё. До двух
   сотых узлов с наибольшей невязкой отбрасываются по одному — сорванная трасса у края листа одна закрывала бы
   перспективу всему снимку, а прогиб, которого модель не описывает, сидит сразу во многих узлах, и такая доля его
   невязку не снимет. Не прошло — перспективы нет, лист меряется прямой гребёнкой.

   Найденная перспектива включает **второй проход**: вырезка выпрямляется уточнённым наклоном, и шаг, фаза и поля
   берутся уже с копии, где строка пикселей совпала с координатой вдоль линий, а сама перспектива — из детектора с
   переводом начала в кадр. Копия живёт только внутри измерения, в разлиновку листа уходят пиксели кадра. Отказ
   второго прохода виден в диагностике и оставляет числа ровного прохода.

   Изгиб (`lib/paper/detectRulingBend.ts`) прослеживается по вертикальным полосам в два шага внутри области с
   линиями: каждая линия ищется с центра и ведётся к краям от предсказания по соседней полосе. Независимый поиск у
   прямой гребёнки к краю цеплял бы соседнюю линию. Одиночные выбросы — соринки, текст, клетки на линии поля —
   снимает медиана соседних линий в том же столбце. Медиана по соседним столбцам срезала бы гребень волны. Изгиб
   проходит **проверку надёжности** и не сохраняется, если найдено меньше 60 % узлов, фильтр заменил больше 20 %,
   где-то смещение дошло до полушага (трасса перескочила на соседнюю линию), соседние линии в узле расходятся
   больше чем на четверть шага или наибольший отход линий от прямой меньше двадцатой шага — в узлах и у краёв
   области, куда он продолжается параболой через три крайних узла строки на полполосы за крайний узел
   (`measureBendDeviation`). Такой лист остаётся ровным, строки на нём идут по прямой наклонной разлиновке,
   отдельного сообщения пользователю нет.

   Границы области с линиями ищутся **трассой вдоль самих линий** — общий модуль `lib/paper/traceRulingLines.ts`,
   тот же, что у перспективы. Трасса стартует у середины, идёт по соседним полосам от предсказания и ведёт местный
   шаг, обновляя его, только если промежуток отличается от прежнего не больше чем на шестую долю: перескочив на
   соседнюю линию, трасса ушла бы по чужому шагу. Окно поиска — треть шага, край области — «окно не помещается», а
   не последняя позиция прямой гребёнки. Окно вокруг прямой гребёнки на снимке с волной у верха листа
   промахивается мимо первых линий, и верхнее поле съезжает вниз на несколько шагов — на живой тетради это
   четырёхкратная ошибка, а не доли пикселя. Боковые границы — линия поля, крайние вертикали клетки и концы горизонтальных линий — прослеживаются так же.
   Итог — положение, ближайшее к области письма, и наружу от меры по среднему профилю он не выходит: изогнутая
   граница не пускает текст за себя, а край блока остаётся прямым.

   Граница области, упёршаяся в край вырезки, полем становится не сама: измерение смотрит по полосам, есть ли
   провал на шаг дальше крайней линии — одинаково у верхней и у нижней границы, — и берёт поле, только если у
   большинства полос его нет. Иначе — фолбэк от
   стороны листа: линии продолжаются за вырезку, и первая найденная не первая на листе. Ручная правка сохраняет
   изгиб и перспективу, только если шаг и фаза в форме совпали с исходными с точностью до показанных сотых:
   смещения и схождения отсчитаны от гребёнки с ними, и при другой гребёнке строки встали бы мимо линий. Правка
   одних полей их сохраняет.
3. **Стор.** `model/useGeneratorStore.ts` — единственный источник правды, один zustand-стор из трёх частей
   (`model/useGeneratorStore.types.ts`). Один, а не три: селекторы параметров страницы читают части сразу, а
   `useShallow` через два стора не работает.

   - **Документ** — то, что сохраняется и попадает в историю: текст, встроенный шрифт, чернила
     (`ink`: `auto`, `tone` из палитры по `toneId` или `custom` со своим цветом), семья, экземпляр листа и его
     закрепление, реализм (ступень `level` из `config/realismLevels.ts` или `custom`, флаги искажений, частоты,
     вариативность контуров), поправка геометрии, запас снизу, параметры сцены без изображения, `runSeed`.
   - **Просмотр** — `pageIndex`, `isSpread`, `zoom` (`'fit'` или доля пикселей кадра).
   - **Ресурсы** — пресет-семьи, свои листы, свой шрифт, своё изображение сцены, скрытый фон.

   Уровень реализма хранится явно, а не выводится сравнением с таблицей: ручной набор, совпавший со ступенью, и
   правка таблицы меняли бы подпись у сохранённых сессий. Выбор ступени пишет её значения, правка любого поля
   реализма ставит `custom`. Цвет чернил и параметры почерка отрисовка берёт только из рецепта
   (`recipe.inkColor`, `recipe.handwriting`), а не из документа напрямую; «Перегенерировать» — `startNewRun`, новый
   `runSeed`. Компоненты подписываются селекторами, на несколько полей сразу — через `useShallow`.

   **История правок** (`model/useGeneratorStore.history.ts`) — `past` и `future` из снимков документа, глубина
   100 шагов, без зависимостей. Правки документа идут через `commit(patch, {coalesceKey})`: набор текста склеивается
   в один шаг в окне 800 мс, слайдер во время перетаскивания пишет значение без шага истории, а шаг ставит на
   `onValueCommit`. Просмотр и ресурсы в историю не попадают. Ctrl/⌘+Z, Ctrl/⌘+Shift+Z и Ctrl+Y перехватываются и в
   поле текста: оно контролируемое, и браузерный undo после программной установки значения непредсказуем.

   **Сессия** — `persist` из `zustand/middleware` под ключом `autograph.session`, `version: 1`: документ плюс
   `isSpread`. Запись дросселируется на 500 мс (`model/sessionStorage.ts`), иначе набор текста писал бы
   `localStorage` на каждый символ; переполнение и запрет хранилища молча выключают сохранение. Чтение проверяет
   каждое поле отдельно (`model/sessionSchema.ts`) и подставляет дефолт только в негодное, а не отбрасывает сессию.
   Ссылки на листы проверяются позже, в `restoreUserSheets` и `setPresetFamilies`: в момент чтения сессии свои
   листы и профили ещё не загружены. Пропавший закреплённый лист снимает закрепление, неизвестная семья меняется на
   первую. Той же проверкой проходит шаг истории, снимок которого ссылается на удалённый свой лист.
4. **Автокалибровка.** `lib/calibrate/deriveGeometry.ts` выводит кегль, межстрочный интервал, верхний и левый
   отступы и ширину блока из разлиновки листа страницы и метрик шрифта (`lib/measure/measureFontMetrics.ts`):
   базовая линия первой строки садится на первую линию не выше верхнего поля, края блока — поля, сужённые линией
   поля. Первая линия и высота под текст считаются в **координате вдоль линий** (`lineCoordinateAt`), а не в
   пикселях по высоте: на листе с перспективой шаг по кадру плывёт, и нижнее поле, отмеренное пикселями, отрезало
   бы слева и справа разное число строк. Без перспективы `U(0, y) = y`, и числа прежние. Геометрия считается на
   каждую страницу — у каждой свой лист. Слайдеры геометрии остались, но задают
   **поправку** поверх вычисленного, как и запас снизу, в долях шага разлиновки: так она одинаково сдвигает текст
   на листах с разным шагом. Модель строчного бокса одна на все слои:
   `lineStep = fontSizePx * lineHeight + lineSpacing`, базовая линия строки n — `topOffset + fontAscent *
   fontSizePx + n * lineStep`, где `lineHeight` и `fontAscent` берутся из `fontBoundingBox`. Разойдись эти формулы
   между расчётом и отрисовкой — строки уползают с разлиновки на треть шага за строку.
5. **Измерение и разбивка.** Ядро не трогает DOM само: `lib/measure/` описывает интерфейс `TextMeasurer` и его
   реализацию на скрытом offscreen-контейнере; ширины он отдаёт в долях кегля, в пиксели их переводит кегль
   страницы. `lib/paginate/` набирает страницы последовательно: каждая раскладывается под разлиновку своего листа
   (`lib/split/` режет текст на строки по ширине её блока за вычетом процента запаса: Linux Chromium раскладывает
   строку целыми пикселями, до 0,9 % шире замера). Строка ставится, пока её базовая линия не ниже нижнего поля
   листа, — хвосты букв последней строки могут зайти в поле. Результат кэшируется в `model/measureLayout.ts`:
   параметры, не меняющие переносы, применяются без повторного измерения.
6. **Рецепт прогона.** `lib/recipe/` выводит из одного seed всё случайное: экземпляр листа на каждую страницу,
   цвет чернил из палитры правдоподобных, параметры неровности почерка, параметры вариативности контуров, оптику
   (качество JPEG). Постраничные величины берутся из независимых подпотоков `seed ^ hash(pageIndex)`, поэтому
   дописанный абзац не перекрашивает чернила и не меняет уже показанные листы. Правка текста рецепт сохраняет,
   смена — только по явному действию.
7. **Отрисовка.** `lib/render/` рисует страницу на canvas: страница равна кадру своего листа, фотография ложится
   на неё целиком, без масштаба и сдвига, чернила — на прозрачный слой. Буквы ставятся контурами глифов
   (`lib/glyph/`), у каждого вхождения свой шум: точки смещаются, но границы стыка с соседней буквой заморожены,
   иначе рвутся соединения связного почерка. Слой чернил прогоняется шейдером `lib/ink/`, который умножает их на
   поле освещения и карту текстуры листа; у листа с непригодным полем (равномерный скан) берётся синтетический
   свет. Чётные страницы — правая половина разворота: фотография и поле освещения отражаются вместе с разлиновкой
   (`lib/paper/mirrorSheetRuling.ts`: линия поля и поля меняют сторону, наклон — знак, фаза сдвигается на наклон
   во всю ширину кадра; у изгиба столбцы узлов идут в обратном порядке, сетка ложится зеркально, а начало строк
   узлов сдвигается на тот же наклон, что и фаза; у перспективы начало переезжает в `W − x₀`, а схождение по
   ширине меняет знак — схождение по высоте и `y₀` отражение не трогает; у контура углы переезжают по горизонтали
   и левые меняются местами с правыми, иначе обход четырёхугольника вывернулся бы и вписанный прямоугольник вышел
   бы за лист). Отражённую разлиновку берут и раскладка, и отрисовка — один селектор в
   `model/geometrySelectors.ts`. Изгиб, перспективу и контур отражает только `mirrorSheetRuling`: параметры
   страницы берут готовые поля из разлиновки страницы.

   **Изгиб и перспектива в отрисовке** — один механизм: точка строки ставится не на `y`, а на `Y(x, U) + d` —
   высоту своей линии в её столбце плюс смещение изгиба. Включается он только при непустом `bend` или
   `perspective`; на ровном листе без перспективы ни выборка, ни перевод координат не вызываются, и лента вызовов
   контекста та же, что у листа без изгиба и перспективы. Рядом со стеком канвы рендерер ведёт ту же матрицу без масштаба и сдвигает каждую
   точку контура, контрольные точки кривых тоже, на разницу между местом линии и `y` в её точке страницы,
   переведённую обратной линейной частью в локальные координаты буквы. Стык соседних букв — одна точка страницы с
   одним сдвигом, поэтому соединения связного почерка не рвутся. Неровность почерка и поправка геометрии уже вошли
   в матрицу, и линия ложится поверх них. Сдвиг точками, а не деформацией готового слоя чернил в шейдере: без WebGL
   он пропал бы вместе с модуляцией, а ленту вызовов тесты попадания уже не видели бы.

   **Побуквенный путь** достаётся буквам без контура: своему шрифту и встроенному, пока его `.ttf` не разобран. На
   изогнутом листе и на листе с перспективой слово рисуется по одной букве. Каждая сдвигается на смещение в
   середине буквы на базовой линии и поворачивается на `atan(tgθ + ∂d/∂x) − θ` — по касательной к своей линии за
   вычетом наклона, уже учтённого матрицей. Целое слово с одним сдвигом осталось бы прямым и в углу листа ушло бы с
   линии больше чем на десятую шага.

   **Раскладка от изгиба не зависит, от перспективы зависит.** Кегль, интервал, отступы, вместимость и переносы
   считаются по гребёнке без изгиба: `lib/calibrate`, `lib/paginate` и отпечаток кэша `model/measureLayout.ts`
   поле `bend` не читают — изгиб сдвигает уже разложенные строки только при отрисовке. Иначе переимпорт листа с
   чуть другим изгибом менял бы число строк на странице. Цена — базовая линия последней строки может уйти ниже
   нижнего поля на величину изгиба, меньше полушага. Перспектива, наоборот, входит и в геометрию, и в отпечаток
   кэша: она меняет сам шаг по кадру, а с ним число строк, и раскладка по прямой гребёнке уводила бы низ страницы
   с линий на целую строку — это не поправка поверх готовой раскладки.
8. **Экспорт.** Предпросмотр и снимок идут **одним** путём и отличаются только масштабом. Отрисовка страниц уехала
   в Web Worker на `OffscreenCanvas`, поэтому интерфейс не замирает; через границу воркера идут только числа и
   строки, фотография передаётся `ImageBitmap`, шрифт и карта текстуры разбираются на его стороне. Растр —
   JPEG в разрешении кадра листа: фотография бумаги не бывает PNG. Пачка (`lib/batch/`) обрабатывает страницы по
   одной — страница кодируется и освобождается до отрисовки следующей, размер у каждой свой, — упаковывает их в
   архив с сортируемыми именами, показывает прогресс и умеет отмену; ошибка отдельной страницы не теряет
   остальные. Вложение страницы в сцену (`lib/export/`) осталось необязательным шагом: фотография листа часто уже
   снята на столе.

В снимок попадает только страница — панель настроек и навигация лежат вне пути отрисовки.

## Ассеты

- Шрифты — `public/fonts/*.ttf`, объявления `@font-face` — в `src/app/styles/app.css`, список для панели —
  в `pages/Generator/config/fonts.ts`. Добавляя шрифт, правь оба места. Отрисовка читает тот же `.ttf` напрямую,
  чтобы получить контуры глифов.
- Пресет-пак листов — `public/paper/{grid,lined}/*.jpg` плюс карты текстуры `*.texture.png` рядом и артефакт
  `public/paper/profiles.json` с разлиновкой каждого экземпляра (контур, шаг, фаза, наклон, перспектива, изгиб,
  поля, линия поля). Артефакт пересчитывается `npm run build:paper` и коммитится: в рантайме фотографии не
  разбираются. Скрипт печатает по каждому листу контур по сторонам и углам, перспективу (шаг у крайних линий,
  дрейф, расхождение гребёнок, причину отказа), наибольший отход изгиба в долях шага — тот же, по которому решает
  проверка надёжности, с краями области, — и долю найденных узлов: по ним сверяются пороги проверки надёжности.
  Пресеты сняты вплотную к листу и без завала, поэтому у всех восьми и `outline`, и `perspective` — `null`; сам
  путь измерения от этого не отличается.

  `npm run measure:sheet -- <фото> [grid|lined|blank]` печатает те же строки по одной фотографии, не трогая
  артефакт: так принимается разбор снимка, которого в пресет-паке нет. Вид просят явно, потому что `blank`
  отключает поиск разлиновки, а клетку от линейки измерение и так различает по снимку.

  Изгиб, контур и перспектива в артефакте и в записи своего листа — необязательные поля `bend`, `outline`,
  `perspective`; смещения изгиба округлены до сотых пикселя ещё при измерении. Отсутствующее или испорченное поле
  читается как «ровный лист», «лист во весь кадр», «линии через равный шаг» (`model/paperSheetJson.ts`), а не как
  сломанная запись: сетка изгиба не по длине `offsets`, контур хоть с одним негодным углом, перспектива, у которой в углу кадра
  знаменатель `w` или `1 − a·q` не больше нуля (одного `1 − a·q` мало: за горизонтом он и числитель меняют знак
  вместе) — всё это `null`, а не отброшенный лист. Поэтому
  `PAPER_PROFILES_VERSION` эти поля не учитывает: поднятая версия заставила бы приложение отбросить весь артефакт.
  Свой лист без них в записи остаётся ровным листом во весь кадр до переимпорта: при запуске фотографии не
  разбираются. Карта текстуры лежит отдельным файлом, а не строкой в артефакте: в base64 это около мегабайта на
  снимок, а файл ещё и кэшируется браузером.
- Семьи листов — `pages/Generator/config/paperFamilies.ts`: вид разлиновки и экземпляры. Без артефакта семьи всё
  равно доступны, но разлиновка экземпляров синтезирована: шаг — доля кадра, поля — фолбэком, фаза нулевая.
- Сцены — `public/bg7.jpg`, `public/bg10.jpg`.
- Пользовательский шрифт подключается через FontFace API под именем `UserFont`; свои листы хранятся локально —
  исходная фотография и производные (освещение, текстура) раздельно, производные пересчитываемы.

  У записи своего листа есть обязательный `isBlank` — лист добавлен без разлиновки. Признак лежит в записи, а не
  выводится из семьи: чистый лист живёт в той же семье клетки или линейки, и перемер по виду семьи искал бы на нём
  линии и затёр бы заданный руками шаг. Обязательность заставляет компилятор переносить признак во всех точках
  добавления; запись прежней формы без поля читается как лист с разлиновкой, а не отбрасывается. Перемер границ
  (`ui/Generator/SettingsPane/useSheetRemeasure/`) заново ищет контур, свет и текстуру, у чистого листа разлиновку не
  трогает, но подтягивает каждое поле до фолбэка от нового контура: ручное поле, оказавшееся снаружи нового листа,
  сдвигается внутрь, иначе текст начался бы за краем бумаги. Клемп живёт в хуке, а не в сборке разлиновки: ту
  зовут импорт, чтение JSON, перечтение хранилища и ручная правка — там он двигал бы ручные поля при каждом чтении.

## Тесты

Четыре слоя:

| Слой | Команда | Что держит |
|---|---|---|
| Юнит | `npm test` | Ядро: контур листа, измерение разлиновки, угла и перспективы, освещение и текстура, перенос, пагинация, автокалибровка, вариативность контуров, модуляция чернил, рецепт прогона, ступени реализма, пачка, детерминизм отрисовки; схема сессии по каждому негодному полю, история правок (склейка, глубина, очистка повтора), форматтеры, лестница масштаба |
| Компонентные | `npm test` | По файлу на область экрана: текст, закреплённые действия и пачка, область просмотра (зум, разворот, навигация клавишами), пикеры оформления, экспертный режим, диалог листа, undo/redo кнопками и клавишами, восстановление сессии и ссылок на листы, стор — jsdom + `@testing-library/react` |
| Stories в браузере | `npm run test:stories` | Настоящий layout: попадание базовых линий на разлиновку на живом измерителе в `SheetViewport`, экран целиком в окне 1440×900 (кнопки действий видны при раскрытом экспертном режиме), разворот, диалог листа, клавиатура, проверки `a11y` |
| Скриншотные | `npm run test:visual` | Внешний вид примитивов, шапки, экрана, области просмотра и диалога листа |

Тесты лежат плоско в `tests/`, хелперы — в `tests/helpers/` (генераторы синтетических листов, контексты-записыватели
вызовов canvas, растеризатор чернил, модель строчного бокса). Компонентные тесты просят jsdom директивой
`@vitest-environment jsdom` в шапке файла; заглушки того, чего в jsdom нет (`ResizeObserver`, `document.fonts`,
`FontFace`, `Range.getClientRects`, canvas), — в `tests/helpers/jsdom-setup.ts`.

Проверки, которые нельзя подменить скриншотом: связность почерка считается числом связных областей чернил в растре
(эталон к разрыву слеп), совпадение прогонов — лентой вызовов контекста **после** рендерера (сравнение входных
параметров не поймало бы случайность внутри отрисовки), попадание на разлиновку — арифметикой по модели строчного
бокса, а не глазами.

Эталоны скриншотов снимаются только в docker-образе Playwright: рукописные шрифты растрируются в macOS и Linux
по-разному. Прогон вне образа не предусмотрен — обе команды (`test:visual`, `test:visual:update`) идут через
`visual:docker`. Seed прогона в stories фиксирован — иначе каждый прогон давал бы другой почерк. Подробности —
`tests/visual/README.md`.

## Линтинг

```
eslint.config.mjs        # flat config: typescript-eslint + prettier + jsdoc + simple-import-sort + unicorn +
                         # react-hooks и jsx-a11y на **/*.tsx
stylelint.config.mjs     # stylelint-config-standard + послабления под Tailwind 4
steiger.config.ts        # границы слоёв FSD
.lintstagedrc.mjs        # eslint --fix / stylelint --fix / prettier --write по staged-файлам
.husky/pre-commit        # lint-staged + tsc + vitest --changed параллельно
```

Осознанные послабления:

- `no-undef` выключен для TS: необъявленное имя ловит `tsc`.
- В stylelint выключены `property-no-vendor-prefix` / `value-no-vendor-prefix`, `import-notation` и разрешены
  at-правила Tailwind (`@theme`, `@apply`, `@layer`, …): Tailwind 4 объявляет тему прямо в CSS, а
  `@import 'tailwindcss'` плагин ищет по строковой форме.

`.claude/hooks/lint.sh` — PostToolUse-хук: после каждой правки гоняет по файлу eslint (+`tsc --noEmit` для `.ts`/
`.tsx`) или stylelint + `prettier --check` для `.css`. Ошибки в правленом файле блокируют правку.
