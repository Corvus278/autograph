# Комментарии

1. JSDoc на русском. Предпочитай JSDoc вместо `//`. *(см. ниже)*
2. Комментарий осмысленный — не повторяет код, объясняет «почему», а не «что». *(см. ниже)*
3. Не скупись на пустые строки между абзацами длинного комментария.
4. Не описывай внутренности принимающей стороны — только observable behavior. *(см. ниже)*
5. Комментарий объясняет, почему код устроен так **сейчас**. История правок — в git. *(см. ниже)*
6. Закомментированный код — не комментарий. Удаляй: он есть в git.
---

## Подробности

### #1. JSDoc на русском

**Why:** конвенция проекта. JSDoc структурно привязан к функции, виден в IDE при вызове и переживает рефактор лучше
плавающего `//`.

```ts
/**
 * Следующий seed — соседнее целое, а не случайное число: соседние seed дают
 * заметно разный рисунок почерка, зато переход предсказуем и проверяется
 * тестом.
 *
 * @param seed — текущий seed искажений
 * @returns seed для следующей перегенерации
 */
```

---

### #2. Почему, а не что

**Why:** «что» уже написано в коде. Ценность комментария — контекст, которого из кода не видно:
зачем так, какие альтернативы отвалились, какой кейс ловим.

**Хорошо:**

```ts
/**
 * Ширину строки складываем из прямоугольников `Range`, а не берём
 * `offsetWidth` контейнера: нужна дробная ширина самого текста, без
 * округления и без отступов обёртки.
 */
```

**Плохо** (повторяет код):

```ts
// присваиваем title значение из контента
const title = content.title;
```

---

### #4. Только observable behavior

**Why:** пересказ внутренностей вызываемого модуля — хрупкая зависимость через текст. Реализацию отрефакторят, и
комментарий начнёт молча врать. Вызывающей стороне важно другое: что вернётся и что будет в краевых случаях.

**Хорошо:**

```ts
/**
 * Возвращает dataURL готовой страницы. Пустая строка — рендер не удался,
 * ссылку на скачивание в этом случае не создаём.
 */
```

**Плохо:**

```ts
/**
 * Дёргает `paginate`, который внутри складывает высоты строк, сравнивает
 * с высотой блока и режет массив на куски.
 */
```

Ссылки на **наши** файлы (`lib/paginate/paginate.ts`, `model/measureLayout.ts`) допустимы — это одна кодовая база.

---

### #5. Про «сейчас», а не про историю

**Why:** «раньше было иначе» устаревает в момент написания и ничего не даёт читателю: перед ним текущий код, а не
предыдущая ревизия. История живёт в git — датированная и связанная с диффом.

**Запрещено:** «раньше здесь было», «до редизайна», «переделали с X на Y», «прежнее поведение сохранено», «вернули как
было».

**Можно:** сослагательное про **альтернативу**, если оно объясняет текущее решение. Это не история, а обоснование
выбора.

**Хорошо:**

```css
/**
 * Строго visible: при overflow-x: hidden вторая ось вычисляется в auto,
 * html снова становится скролл-контейнером и пропагация ломается.
 */
```

**Плохо:**

```css
/**
 * Тут был overflow: hidden, потом поменяли на auto, но поехала карта
 * кликов. В итоге откатили и поставили visible.
 */
```
