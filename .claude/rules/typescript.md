# TypeScript

1. Типы/интерфейсы — в отдельных `*.types.ts` рядом с кодом. Глобальные декларации для вендорных глобалов — в
   `src/types/*.d.ts` (собственный код) и `tests/types.d.ts` (заглушки тестов).
2. Предпочитай типы интерфейсам
3. По умолчанию — `const enum` или `as const`-объекты. Обычный `enum` — только там, где нужно runtime-значение (поля
   react-hook-form, `Object.values`, передача между модулями).
4. `any` запрещён (`@typescript-eslint/no-explicit-any`). Не типизируется — бери `unknown` и сужай проверкой.
5. Type-гарды (через оператор `in`) — держи функциями рядом с соответствующими типами.
6. В рамках одного файла допустимо задавать алиасы, чтобы упростить чтение типов. _(см. ниже)_
7. `Array<T>` → `T[]`.
8. Не инлайни типы в теле функции — выноси в `*.types.ts`.
9. Не кастуй через `as` без обоснования. _(см. ниже)_
10. Тесты — в `/tests`, плоско: `tests/<модуль>.test.ts`. Не раскладывать по `__tests__` и не класть рядом с кодом.
11. Тест-утилиты — только в `tests/helpers/` (файл на утилиту: `jsdom-setup.ts`, `monospace-measurer.ts`).
    Ссылаться на них из `src/` нельзя.
12. JSDoc обязателен для каждого поля типа (`type`/`interface`); описание — непустое и осмысленное. На сам тип — по
    желанию, только если имя не объясняет назначение. *(см. ниже)*

## Подробности

### #6. Локальные алиасы для читаемости

**Why:** длинные generic-цепочки в сигнатуре нечитаемы. Локальный `type` улучшает читаемость, не засоряя публичный
`*.types.ts`.

**Хорошо:**

```ts
type Row = Pick<LeadDetails, 'id' | 'name' | 'price'>;
type RowsByStatus = Record<LeadStatus, Row[]>;

const groupRows = (rows: Row[]): RowsByStatus => {
  return groupBy(rows, 'status') as RowsByStatus;
};
```

**Плохо:**

```ts
const groupRows = (
  rows: Pick<LeadDetails, 'id' | 'name' | 'price'>[]
): Record<LeadStatus, Pick<LeadDetails, 'id' | 'name' | 'price'>[]> => {
  return groupBy(rows, 'status') as Record<
    LeadStatus,
    Pick<LeadDetails, 'id' | 'name' | 'price'>[]
  >;
};
```

### #9. Не кастуй через `as` без обоснования

**Why:** `as` отключает проверку компилятора. Если ты ошибся в касте, баг доедет до продакшена молча. Каст всегда —
рабочая гипотеза автора, что данные соответствуют типу; чем больше `as`, тем выше шанс, что одна из гипотез когда-то
протухнет.

**Когда `as` оправдан:**

- `as const` — фиксация литерального типа, не каст;
- сразу после type-guard / рантайм-валидации (zod, своя `isFoo`);
- сужение `unknown` после явной проверки;
- TypeScript-bug, когда вывод действительно не работает (с комментарием-обоснованием).

В остальных случаях — переписывай типизацию, а не глуши `as`.

**Хорошо** (`as const`):

```ts
const STATUSES = ['draft', 'active', 'archived'] as const;
```

**Хорошо** (после type-guard — каст не нужен):

```ts
const isUser = (value: unknown): value is User => {
  return !!value && typeof value === 'object' && 'id' in value;
};

if (isUser(data)) {
  sendInvite(data); // data: User — без as
}
```

**Плохо** (каст без проверки):

```ts
const user = response.data as User;
// если backend вернёт что-то другое — узнаем только в рантайме
```

**Плохо** (двойной каст для обхода ошибки типов):

```ts
const config = rawValue as unknown as Config;
// заглушили TS вместо того, чтобы исправить типизацию
```

**Плохо** (каст частичной структуры):

```ts
const config = { theme: 'dark' } as Config;
// Config требует ещё полей, но as промолчал
```

### #12. JSDoc для полей типа

**Why:** поле без описания заставляет читать использования, чтобы понять семантику. Особенно неочевидное — что означает
`null`, граничные кейсы, связь полей. Машинно проверяется, чтобы требование не зависело от ревьюера.

Само имя типа обычно уже говорит, что это (`ButtonProps`, `ScrollLockSnapshot`), поэтому блок над объявлением не
обязателен. Пиши его, когда назначение типа из имени не выводится или у типа есть неочевидный инвариант, связывающий
поля.

**Enforce:** `jsdoc/require-jsdoc` (наличие блока) + `jsdoc/require-description` (непустое описание) на
`TSPropertySignature`. В описании — семантика поля, а не пересказ типа; для колбэков — «Колбэк на [действие]».

**Хорошо:**

```ts
type CouponParams = {
  /**
   * Код купона. null — купон не применён.
   */
  code: string | null;

  /**
   * Колбэк на применение купона.
   */
  onApply: (code: string) => void;
};
```

**Хорошо** (блок над типом — имя не объясняет, к какому моменту относится снапшот):

```ts
/**
 * Снапшот inline-стилей, снятый перед локом скролла — для восстановления при разлоке.
 */
type ScrollLockSnapshot = {
  /**
   * Inline-значение `overflow` у `body`. Пустая строка — свойство не было задано.
   */
  overflow: string;
};
```

**Плохо** (нет описаний у полей):

```ts
type CouponParams = {
  code: string | null;
  onApply: (code: string) => void;
};
```
