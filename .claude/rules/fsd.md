# Feature-Sliced Design — правила

1. Новый код — в один из слоёв `pages → widgets → features → entities → shared` по page-first (по умолчанию `pages`;
   выше — только при втором реальном потребителе; stories и тесты потребителями не считаются).
2. Сегменты слайса: `ui`, `model`, `lib`, `config`. `hooks`, `utils`, `types`, `constants` — запрещены.
3. В корне слайса — только сегменты-директории и `index.ts`, ничего постороннего.
4. Файлы `shared/lib` — в поддиректории по области применения, не в корне сегмента.
5. Подкомпоненты — рядом с родителем в `ui/<Component>/<SubComponent>/` (без папки `components/`), приватны для него;
   собственные сегменты подкомпонента доступны только ему, не потомкам.
6. Бизнес-логика — в `model` (рядом с потребителем; общая для поддерева — сразу в корневой `model` слайса): стор,
   селекторы, оркестрация поверх ядра. Чистые алгоритмы без состояния — в `lib`. В `ui` — рендер, локальное состояние,
   ввод.
7. Public API — `index.ts`: только именованные экспорты, без `export *`, без `as`. Имя слайса/компонента уникально в
   источнике.
8. Внутри модуля — относительные импорты; между слайсами — через Public API; `from '../'` (свой `index.ts`) нельзя —
   внутри слайса импортируй напрямую из нужного модуля.
9. Зависимости только сверху вниз; cross-импорты на одном слое запрещены.
10. Имена: компоненты и слайсы — `PascalCase`, утилиты/хуки — `camelCase`, имя папки = имя главного файла.

Границы слоёв проверяет `npm run lint:fsd` (steiger), он же входит в `npm run lint`.
