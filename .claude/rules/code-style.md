# Стиль кода

1. Только именованные экспорты (никаких default).
2. Предпочитай ES6-методы (`find`, `flatMap`, `Object.entries`). lodash в проекте нет — не тащи его ради одной утилиты.
3. Используй явный `return`, если функция возвращает значение.
4. `switch` предпочтительнее `if` — ради будущей расширяемости. *(см. ниже)*
5. Пустая строка в конце файла.
6. `||` — дефолт по умолчанию. Осознанный выбор: falsy-коэрсия (0, '', false → дефолт) принята как норма. Исключение из
   правила про явное приведение типов. *(см. ниже)*
7. Выноси в константу, если значение повторяется или его семантика неочевидна. Тривиальные литералы (0, 1, '',
   уникальные для одного места) можно оставлять инлайном.
8. Используй `async/await` вместо `.then()`.
9. Не оборачивай строковые пропсы в фигурные скобки — не `{"m"}`, просто `"m"`.
10. Деструктуризация при любой возможности.
11. Условия Йоды (`'x' === getType()`) запрещены.
12. Присваивание внутри условия запрещено.
13. Function declaration — только для перегрузок, иначе — стрелочная функция.
14. Комментарии и jsdoc — на русском. Предпочитай jsdoc вместо `//`.
15. Экономь проходы по коллекции — заменяй цепочки `.filter().map()` (и обратные) на `.reduce`, если результат идёт в
    массив одного типа. *(см. ниже)*

## Подробности

### #4. `switch` предпочтительнее `if`

**Why:** при exhaustive-проверке union/enum компилятор подскажет, если добавили новый кейс в перечисление. `if/else` так
не умеет.

**Когда применять:** перебор значений enum / string-литерального union из ≥2 вариантов. Бинарную проверку (
`if (cond) return a; return b;`) оставлять `if`.

**Хорошо:**

```ts
switch (position) {
  case 'top':
    return {left: '50%', bottom: '-1.5px'};
  case 'bottom':
    return {left: '50%', top: '2.5px'};
  case 'left':
    return {top: '50%', right: '0px'};
  case 'right':
    return {top: '50%', left: '0px'};
  default:
    throw new Error(`Unknown position: ${position}`);
}
```

**Плохо:**

```ts
if (position === 'top') {
  return {left: '50%', bottom: '-1.5px'};
}

if (position === 'bottom') {
  return {left: '50%', top: '2.5px'};
}

if (position === 'left') {
  return {top: '50%', right: '0px'};
}
// добавили 'right' в union — TS не подскажет, что забыли обработать
```

### #6. `||` как дефолт (falsy-коэрсия)

**Why:**

- в проекте принято: пустая строка/0/false из API/DOM = «значения нет». `??` оставит `''` или `0` — это другое поведение
  и обычно баг;
- `||` короче в скомпилированном виде: `??` транспилируется в проверку `!== null && !== undefined` (две операции),
  `||` — одна falsy-проверка. На горячих путях и в больших бандлах разница накапливается.

**Хорошо:**

```ts
const inputType = inputEvent.inputType || ''; // null | undefined | '' → ''
```

**Хорошо:**

```ts
const fillWidth = fillWidths[index] || 0; // отсутствие или 0 → 0 (валидно)
```

**Когда уместен `??`:** только если осознанно нужно отличать `0` или `''` от `null/undefined`. В этом случае обязателен
комментарий, объясняющий, почему `||` неприменим.

```ts
// нужно сохранить выбор '0 секунд' пользователя; '' и undefined считаем «не выбрано»
const delay = userDelay ?? DEFAULT_DELAY;
```

### #14. Комментарии

Комментарии надо писать в jsdoc стили, в несколько строк
**Хорошо:**

```js
/**
 * Текст комментария
 */
```

**Плохо:**

```js
/** Текст комментария */
```

**Плохо:**

```js
// Текст комментария
```

### #16. Экономь проходы по коллекции

**Why:** `.filter(...).map(...)` — это два прохода по коллекции и промежуточный массив, который сразу же выбрасывается.
Один `.reduce` за один проход делает оба шага и не создаёт мусор. Производительность важнее читаемости — лишний проход
не оправдывается «так короче».

**Когда применять:** любая цепочка из двух и более методов-итераторов (`.filter().map()`, `.map().filter()`,
`.filter().filter()`, `.map().map()`, и т.п.) сворачивается в один `reduce`. Дженерик `reduce<T[]>` снимает каст
аккумулятора.

**Когда оставлять как есть:** только одиночный вызов — просто `.filter`, просто `.map`, просто `.find` — там сворачивать
нечего.

**Хорошо:**

```ts
const fontOptions = HANDWRITING_FONTS.reduce<SelectOption[]>((acc, font) => {
  if (isFontReady(font.family)) {
    acc.push(toSelectOption(font));
  }

  return acc;
}, []);
```

**Плохо** (две итерации + промежуточный массив):

```ts
const fontOptions = HANDWRITING_FONTS.filter((font) => {
  return isFontReady(font.family);
}).map(toSelectOption);
```
